# Архитектура Arbitr AI

## Компоненты

| Слой | Компонент | Технологии |
|------|-----------|------------|
| Frontend | Веб-кабинет управляющего | React 18, TypeScript, Vite, Ant Design |
| Backend | API-шлюз, бизнес-логика | Python 3.12, FastAPI |
| AI-ядро | LLM + база знаний | GPT-4 / YandexGPT, LangChain, RAG (FAISS) |
| Очереди | Асинхронные задачи | Redis + Celery |
| БД | Основное хранилище | PostgreSQL 16, Redis (кэш) |
| Файлы | Документы, сканы | MinIO (S3-совместимый) |
| Интеграции | Госорганы, почта, ЭЦП | REST/SOAP/СМЭВ, API Почты России, КриптоПро |
| RPA | Автоматизация порталов | Playwright |
| DevOps | CI/CD, флаги, секреты | Harness, Kubernetes, Terraform, Helm |
| Мониторинг | Логи, метрики | Prometheus, Grafana, Loki, structlog |

## Модель данных

```
users ──< cases ──< debtors
                ├──< creditors
                ├──< properties
                ├──< documents
                └──< requests ── document
```

- **users** — пользователи (управляющий, администратор, помощник, наблюдатель)
- **cases** — дела о банкротстве (суд, регион, статус, процедура, сроки)
- **debtors** — должники (ФИО, ИНН, СНИЛС, паспорт, адрес)
- **creditors** — кредиторы (наименование, ИНН, сумма требования, статус в реестре)
- **properties** — имущество (тип, кадастровый номер, стоимость, арест)
- **documents** — документы (тип, ключ в MinIO, версия, AI-генерация)
- **requests** — запросы в госорганы (тип, статус, способ отправки, ШПИ)

## Статусы запросов

```
draft → pending → sent → delivered → waiting → (partial) → response
                                          ↘ rejected / error
```

## Способы отправки

1. **API** — прямое взаимодействие (СМЭВ, api-fns.ru, api-ip.fssp.gov.ru)
2. **e_letter** — электронное заказное письмо через API Почты России
3. **RPA** — автоматизация личных кабинетов порталов (Playwright)
4. **manual** — ручная отправка с фиксацией в системе

## Механизм защиты секретов

- Все ключи и пароли — только через **Harness Secrets Management** (инъекция в рантайм)
- В коде — переменные окружения (pydantic-settings), никаких хардкодов
- Feature Flags — гейтинг интеграций (ФНС, Росреестр, AI, RPA)

## Отказоустойчивость

- 2+ реплики каждого сервиса в Kubernetes
- Rolling Update / Blue-Green деплой через Harness
- Health-check / readiness-probe на каждый сервис
- Автоматический откат при провале пост-деплой проверок
- Резервное копирование БД и файлов ежедневно
